        [out] **Garbage Collection in Python**

Python's garbage collection is a mechanism that automatically frees up memory occupied by objects that are no longer needed or referenced.

Here's a simplified overview:

1. **Object Creation**: When an object is created, Python allocates memory for it.
2. **Reference Counting**: Each object has a reference count, which is the number of variables that reference the object. When the reference count reaches 0, the object is considered garbage.
3. **Garbage Collection Cycle**: Python periodically runs a garbage collection cycle, which:
	* Iterates through all objects in memory.
	* Decrements the reference count of each object.
	* Frees memory occupied by objects with a reference count of 0.
4. **Finalization**: When an object is garbage collected, Python may call its `__del__` method (if defined) to perform any necessary cleanup.

**Example**:
```python
import gc

class MyClass:
    def __init__(self):
        print("Object created")

    def __del__(self):
        print("Object deleted")

obj = MyClass()
obj = None  # Remove reference
gc.collect()  # Trigger garbage collection
```
Output:
```
Object created
Object deleted
```

1. **Consistency**: All nodes in the system see the same data value for a given data item.
2. **Availability**: Every request to a non-failing node in the system receives a response, without the guarantee that it contains the most recent version of the information.
3. **Partition tolerance**: The system continues to function and make progress even when there are network partitions (i.e., when some nodes in the system cannot communicate with each other).

**Step 1: User Request**
A user types a URL into their browser, e.g., `example.com`.

**Step 2: DNS Query**
The browser sends a DNS query to the operating system's DNS resolver, which is usually provided by the internet service provider (ISP).

**Step 3: DNS Cache**
The DNS resolver checks the DNS cache, a local memory store that contains recently resolved domain names. If the domain name is cached, the resolver returns the cached IP address.

**Step 4: Recursive DNS**
If the domain name is not cached, the DNS resolver sends a recursive DNS query to a root DNS server (e.g., `8.8.8.8`).

**Step 5: Root DNS Server**
The root DNS server receives the query and directs it to a top-level domain (TLD) server (e.g., `.com`).

**Step 6: TLD Server**
The TLD server receives the query and directs it to a name server (e.g., `ns1.example.com`).

**Step 7: Name Server**
The name server receives the query and returns the IP address associated with the domain name.

**Step 8: DNS Resolution Complete**
The DNS resolver receives the IP address and returns it to the browser, which can then establish a connection to the server.
